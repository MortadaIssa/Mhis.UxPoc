There are mainly two user types who access this web application, NGO or what they call organization and the admin user.
NGOs can register a new profile, fill the main data and after approval they can proceed defining the facilities (places where they perform their activities), register their activities, some activities are of type events that can be either public or private, and they also see the calendar to check after their private events or any public event from other NGOs. they can see notifications that can be events, actions to perform the system ask them to do, announcements sent by admin users. after filling activities the NGOs login to the application to see dashboards and reports about their activities. Dashboard are inside the web application and some advanced dashboards are power BI with a link from the web application to see them. the web application provides several informational pages such as about NMHP, about 4Ws, About MHIs, What is new, Glossary of terms etc. where text can be read and PDF documents can be downloaded. the NGO user can change their password, forgot password is an option at login screen. Some NOGs who logged specific type of activities then they are eligible to access the substance use feature that enables them to log their surveys to the system as well. The application also has a contact us form.
Facilities logged in the system has a support life time by an NGO, start and end date. so an NGO might be supporting a facility for a period of time and then stops. the idea is that at facility creation the NGO should specify the start time and if they know when i ends they need to add as well the end time. This introduced another functionality provided by the system, where a worker always monitor facility that has not been reviewed for more than 6 months and send a notification to the NGO, when the NGO clicks on the push notification they can access a page where they review all facilities that has not been reviewed during a 6 months period, to adjust the end data if they stopped supporting it. in case they ignore this they will not be allowed to add any new activity before they confirm the validity of the list of unreviewed facilities.

There is one functionality that is for NGOs as well but let us consider it as a guest user data, so no need to login and you can see these information. when you visit the web application you can see the list of activities in a grid with a filter where you can choose the activity type and the location and you can see basic information about the activities.

The admin user can login to the application to perform different tasks, one task is approving the logged data, for example. an NGO who registers will not be able to continue creating activities before the admin reviews his profile data, make sure he is an authentic NGO and then approve this user to let them continue logging their data. the Admin can at any time stop an NGO from accessing the system.
If an NGO added an activity of type event, this event should be approved by the admin, or may be rejected or they ask the NGO for modification. Admins can export the whole events of all NGOs as an excel sheet.
Another type of review process is when an NGO add a facility, this facility might be previously supported by another NGO and has an existing record in the system. In reports and dashboards, facilities should be some times displayed as distinct and other times displayed as separate entity to show the life cycle.
for this purpose, and because the NGOs are not experienced in system knowledge, they will not be able to find out that this is already an existing facility (physically) and they go and search for it and link instead of creating new one, so we made it much more easier and safe, so the NGO enter the new facility and we search for similar ones in the DB according to the location with tolerance like 20 meters. only if there are similar facilities, we drop a review record for the admin. the admin has a page where they can see all new facilities that are subject to be already existing physically, and decide if yes they are the same, he adds the new facility to the group of existing one(s). 
One more review functionality the admin performs is accepting the new lookup values. Because some of the lookups might have options that need to be entered by NGOs and does not exist between the lookup values, for this purpose the system gives the NGO the ability to enter a custom value where the admin can review all custom values, and either accept them as new values or merge them to an existing value.
One more functionality is the announcements feature, where the admin can define a list of announcements groups, where in each group the admin defines the criteria to whom this should go to which list of NGOs, and each time the admin needs to send an announcement they just select this group record and craft a new announcement text before sending it. they can also see a list of announcement logs.
